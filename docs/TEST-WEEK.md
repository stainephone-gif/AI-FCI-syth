# Тестовая неделя: пошаговая инструкция

Цель: неделю вести канал-дублёр через бота как в бою, ничего не публикуя в
настоящий канал, и к концу недели знать, что править в промптах, источниках
и карточке. Время редакции: 10–15 минут в день плюс полчаса на запуск.

Шаги 1–3 делает редакция без программиста. Шаг 2 требует терминала, но все
команды даны для копирования.

## 0. Что понадобится

- Два редактора с Telegram.
- Банковская карта для аренды сервера (около 500–1000 ₽ в месяц).
- Ключ Claude API.
- Час времени в первый день.

## 1. Telegram (15 минут)

1. **Создать бота.** Написать @BotFather команду `/newbot`, задать имя и
   username (например `ii_i_fki_editor_bot`). BotFather пришлёт токен вида
   `123456789:AAF...`. Сохранить в менеджер паролей, в чаты не пересылать.
2. **Выключить приватность бота.** В @BotFather: `/setprivacy` → выбрать
   бота → `Disable`. Иначе в группе бот не увидит обычные сообщения
   редакторов, а они нужны для правок и ввода времени.
3. **Создать канал-дублёр.** Новый канал «ИИ и ФКИ · тест». Сделать его
   приватным. Добавить бота администратором с правами «Публикация сообщений»
   и «Изменение сообщений».
4. **Создать чат редакции.** Новая приватная группа «Редакция ИИ и ФКИ».
   Добавить обоих редакторов и бота. Бота можно сделать администратором,
   чтобы он точно видел все сообщения.
5. Id канала и чата понадобятся на шаге 2.6, их подскажет сам бот.

## 2. Сервер (30 минут)

1. **Арендовать VPS.** Любой хостинг: Timeweb, Selectel, Hetzner, Яндекс
   Облако. Тариф: 2 ядра, 4 ГБ памяти, 20 ГБ диска, Ubuntu 24.04. Меньше
   памяти не стоит: браузер для карточек прожорлив. Получить IP-адрес и
   доступ по SSH (пароль root или ключ). Проверить, что с сервера доступен
   API моделей; у некоторых провайдеров это зависит от страны размещения.
2. **Зайти на сервер.** На своём компьютере в терминале:
   ```bash
   ssh root@IP_АДРЕС
   ```
3. **Поставить Docker.**
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
4. **Скачать проект.** Пока код лежит в рабочей ветке:
   ```bash
   git clone -b claude/fervent-maxwell-uqv3j7 https://github.com/stainephone-gif/AI-FCI-syth.git /opt/ai-fci-syth
   cd /opt/ai-fci-syth
   cp .env.example .env
   ```
5. **Заполнить `.env`, первый проход.** Открыть файл: `nano .env`. Вписать
   `BOT_TOKEN` и `ANTHROPIC_API_KEY`. `EDITOR_IDS` оставить пустым,
   `CHANNEL_ID` оставить как есть. Сохранить: Ctrl+O, Enter, Ctrl+X.
6. **Первый запуск в режиме настройки.**
   ```bash
   docker compose up -d --build
   docker compose logs -f bot
   ```
   Сборка занимает 3–5 минут. В логе должна появиться строка про режим
   настройки. Ctrl+C выходит из просмотра лога, бот продолжает работать.

   Теперь каждый редактор пишет в чате редакции `/whoami`. Бот отвечает
   двумя числами: id редактора и id чата. Чтобы узнать id канала, переслать
   любой пост из канала-дублёра в чат редакции и написать `/whoami` ответом
   на пересланное сообщение: бот добавит третью строку с id канала.
7. **Заполнить `.env`, второй проход.** `nano .env`:
   ```
   EDITOR_IDS=111111111,222222222
   EDITOR_CHAT_ID=-1001234567890
   CHANNEL_ID=-1009876543210
   ```
   Перезапустить:
   ```bash
   docker compose up -d --build
   ```
8. **Проверить.** В чате редакции `/status`. Бот должен ответить числом
   редакторов 2, числом источников и двумя задачами планировщика на 06:00
   и 09:00.

## 3. День 0: первая проверка (30 минут)

Всё делается в чате редакции. Ожидаемый результат в скобках.

1. `/collect` (через одну-две минуты отчёт: сколько источников опрошено,
   сколько новых, и список из десяти заголовков с оценками). Если у
   какого-то источника ошибка, записать его название: адрес фида нужно
   будет поправить в `sources.yaml`.
2. `/digest` (через две-три минуты два-три сообщения: карточка, текст
   черновика, кнопки). Прочитать черновики глазами читателя канала.
3. **Правка.** Ответить на текст черновика сообщением «сделай короче и
   убери второй абзац» (через минуту новая версия v2 с теми же кнопками).
4. **Другое время.** Нажать «Другое время», написать время через пять минут
   от текущего, например `14:37` (бот подтверждает, `/queue` показывает
   пост). Через пять минут пост появляется в канале-дублёре, в чат приходит
   «опубликован» со ссылкой.
5. **Отмена.** На другом черновике нажать «Опубликовать 18:00», затем
   `/cancel N` с номером поста (пост снят, черновик с кнопками пришёл
   заново). Нажать «Отклонить».
6. **Ручной ввод.** `/post в четверг семинар лаборатории про ИИ-агентов,
   начало в 18:00, регистрация не нужна` (черновик-анонс с карточкой
   «Лаборатория» и блоком «Проверьте даты»). Убедиться, что четверг
   посчитан верно.
7. **Два редактора.** Найти черновик с пометкой ⚠️ или дождаться его.
   Первый редактор нажимает «Опубликовать» (бот просит подтверждение).
   Тот же редактор нажимает «Подтвердить» (отказ). Второй редактор
   нажимает «Подтвердить» (пост в очереди).
8. `/publish N` для поста из очереди (публикуется сразу).

Если какой-то пункт не сработал, скопировать ответ бота и последние строки
лога (см. раздел 5) и прислать разработчику.

## 4. Каждый день недели

- **06:00** бот собирает источники, **09:00** присылает черновики. Ничего
  запускать не нужно.
- **09:00–09:15** редактор читает черновики и по каждому делает одно из
  четырёх: публикует, правит и публикует, отклоняет, откладывает.
- **Один раз в день** записать в журнал наблюдений строку на каждый
  черновик:

| Дата | № поста | Решение | Что не так | Куда это относится |
|---|---|---|---|---|
| 15.09 | 12 | опубликован после правки | заголовок не вопросом | стайлгайд |
| 15.09 | 13 | отклонён | пересказ пресс-релиза | ранжирование |
| 15.09 | 14 | опубликован как есть | | |

Столбец «Куда относится» выбирается из: стайлгайд, ранжирование,
источники, факты, карточка, бот. По нему в конце недели будет видно, что
чинить.

- **Новости лаборатории** вводить через `/post`, чтобы проверить анонсы
  на реальных случаях.
- **Не трогать** настоящий канал: `CHANNEL_ID` всю неделю указывает на
  дублёр.

## 5. Если что-то сломалось

Посмотреть последние строки лога:
```bash
ssh root@IP_АДРЕС
cd /opt/ai-fci-syth && docker compose logs --tail=200 bot
```
Перезапустить бота:
```bash
docker compose restart bot
```
Обновить код после правок разработчика:
```bash
git pull && docker compose up -d --build
```
Разработчику присылать: текст ответа бота, строки лога, номер поста.
Токен и ключ из `.env` не присылать никогда.

## 6. Конец недели: разбор (1 час)

1. Посчитать по журналу: сколько черновиков опубликовано как есть, сколько
   после правки, сколько отклонено. Ориентир для хорошего результата:
   не меньше трети без правок, не больше трети отклонено.
2. Сгруппировать «что не так» по столбцу «Куда относится». Самая частая
   группа чинится первой.
3. Решить:
   - какие источники убрать или добавить в `sources.yaml`;
   - что дописать в стайлгайд, какие три поста сделать эталонными;
   - нужен ли отдельный порог для образовательных источников (открытый
     вопрос из архитектуры);
   - текст пометки о генерации для `POST_FOOTER`.
4. Переход на боевой канал: добавить бота администратором в настоящий
   канал, в `.env` поменять `CHANNEL_ID`, заполнить `POST_FOOTER`,
   перезапустить, опубликовать закреп с описанием процесса.

## 7. Правила на всё время

- Ничего не публикуется без нажатой кнопки. Если бот опубликовал что-то
  сам, это ошибка, о ней нужно сообщить сразу.
- Токен бота и ключ API живут только в `.env` на сервере.
- Доступ к чату редакции только у редакторов из `EDITOR_IDS`.
